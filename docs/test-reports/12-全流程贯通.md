## 4. 断点/问题清单（按严重度）

1. **【高·根因】数据库缺失行情价格表，导致手动下单 500、评估无法判定、模拟决策为空**
   - `calliper_trading` 库**不存在** `stock_prices_daily` / `stock_prices_1min`（`psql … select count(*) from stock_prices_daily` → 关系不存在）。
   - `MockBroker.getRealPrice`（`mock_broker.go`）硬编码查询表名 **`stock_price_dailies`**（与模型实际 `stock_prices_daily` 不一致，且目标表不存在）→ 市价单取价 0 → `POST /trading/order` 返回 500（response body 为空）、“无法获取 600000 的实时价格”。**影响：E2E-004/006/008 的下单/持仓/资金勾稽全部阻断。**
   - `EvaluationService.getActualChange`（`evaluation_service.go`）读 TSDB `stock_prices_daily` 无数据 → 所有新预测“无行情顺延”（success 保持 NULL），无法产生 correct/wrong。**影响：E2E-005/010 的新预测评估回写链路。**
   - 实时行情/K线不受影响：由外部 Sina 行情 API 实时拉取（`market_handler.go` → fetchSina…），故 realtime/kline 正常。
   - 建议：把 stock 价格数据写入/接入 `stock_prices_daily`（或修正 MockBroker 表名+数据源），即可解锁 004/006/008/009 及评估判定。

2. **【中】sim/status 运行标志不一致**：E2E-001 时 `data.running=true`，后续多次调用返回 `false`；且顶层 running 与 `account.is_running` 字段口径不同。符合已知缺陷“模拟交易 start 因 HTTP ctx 不保持后台运行”。建议确认调度器生命周期与状态持久化。

3. **【低·数据】老用户自选为空**：testuser 初始 watchlist=[]，需先手工添加 600000/600004 才能继续；且 AAPL/TSLA/00700 不在 stocks（仅国产 202 只），批量行情用 600000/600004 替代。

4. **【低·口径】E2E-002 step7 交叉核对不可直接互换**：`accuracy_total` 源自 `prediction_accuracies` 历史评估（短周期 13/35≈37.1%，窗口 36.67%）；当前 600000 新预测全部 pending（success NULL）。predictions.status 与 prediction_accuracies 粒度不同，公式 `correct/(correct+wrong)≈accuracy_total` 在“全部待验证”状态下无意义。属口径差异，非数据错误。

5. **【提示】训练 run / 重训类步骤全部跳过**：按用户要求不做训练，E2E-003 S4、E2E-005 S7~S9、E2E-008 S2 用只读（training/history、models/status、model_health）替代验证，均符合预期口径。

6. **【提示】前端端口 3000**：文档写 5173，实际前端在 3000；E2E-011 及 E2E-006/010/011 的 UI 交互标注“UI 部分待浏览器自动化”。

7. **【提示】WS quote 即时推送依赖行情 ingest**：WS 握手(101)/订阅/ping-pong 已验证可用；quote 是否即时到达取决于行情数据是否被投递到 Redis `quote:updates`（本窗口 feed 静默，6s 内未收到即时 quote，属环境 feed 活跃度问题而非 WS 管道故障）。
