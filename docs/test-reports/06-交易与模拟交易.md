## 重要环境事实（影响判定）

1. **REAL_TRADING_ENABLED=false**（实测：admin 提交 `is_real:true` 仍返回 `is_real:false`）→ 真实交易门禁用例按关闭态断言。
2. **主库无价格表**：MockBroker.getRealPrice 用原始 SQL 查 `stock_price_dailies`（该表不存在；正确表名 `stock_prices_daily` 位于 TSDB `calliper_tsdb`，主库无副本）→ 每次取价返回 0。影响：**市价单/0 价一致报 `50001 下单失败: 无法获取 600000 的实时价格`**；`/trading/account` 与 `/sim/account` 的 `market_value` 恒为 0。
3. **手动模拟下单不扣 SimAccount 资金**：`trade_service.PlaceOrder` 仅写 `orders`+`positions`（按 user_id 隔离），**不改 `sim_accounts(available_cash)`**。故下单后 `available_cash` 与 `total_assets` 不变、`market_value=0`，与 spec「余额减少/市值增加」的金额勾稽不符（TRADE-017/040）。
4. **模拟持仓/账户为跨用户共享池**：`/sim/positions` 与 RiskManager 从 `positions WHERE is_real=false` 读取**所有用户**的模拟持仓（含测试期间 user/admin 手工单）。
5. **HTTP `/sim/start` 无法保持运行（缺陷）**：`StartScheduler(ctx)` 传入 HTTP `request context`，请求返回即 ctx 取消 → 调度 goroutine 立即退出；只有启动时 main.go 用 `bgCtx` 自动启动的常驻调度器可长期运行。故 stop/start 后再查 `running/is_running=false`，重复 start 返回「已启动」而非「已在运行中」。
6. **SIM 决策恒为 0**：库中有效预测 26 条，但每一轮决策均「生成 0 条交易决策」（无 buy/sell 产出）。推测原因：当前有效预测的股票未命中 is_active Top20 / 目标价换算的预期收益排序后方向+置信度(≥60)不达买入/卖出门槛 / 或价格数据缺失。由此 SIM-017/018/039 等仓位/资金勾稽用例无法被实际成交覆盖。

## 三、问题清单（缺陷 / 差异）

**P0（功能不可用/数据一致性）**
1. **市价单与账户市值不可用**：MockBroker.getRealPrice 查询不存在的 `stock_price_dailies`（正确表 `stock_prices_daily` 仅在 TSDB，主库无副本）→ 市价单/0 价一律 `50001 无法获取实时价格`，`/trading/account` 与 `/sim/account` 的 market_value 恒为 0。影响 TRADE-021/022/005b、TRADE-017/040 市值勾稽、SIM-017/018/039 决策与止损结算。**属代码/部署缺陷（real_price 读表名错误+主库缺价格数据）。**

2. **手动模拟下单不改账户余额**：`TradeService.PlaceOrder` 只写 orders+positions，不更新 `sim_accounts.available_cash`；`/trading/account`（mockbroker 读同一 SimAccount id=1）在下单后余额/总资产不变、市值恒 0，**与 spec「下单后余额减少、持仓市值增加」勾稽不符**（TRADE-017/040）。

3. **HTTP `/sim/start` 无法保持调度器运行**：`StopScheduler/StartScheduler` 用 HTTP request context，请求返回即 ctx 取消 → goroutine 立即退出。仅 main.go 启动期 `StartScheduler(bgCtx)` 的实例可长期运行。由此 SIM-002（start 后 running 回到 false）、SIM-003b（重复 start 不幂等）失败。**建议改为使用不受请求生命周期影响的 context。**

**P1（校验缺口 / 按缺陷记录）**
4. **价格与数量无负值/零值校验**：`price:"-1"` 成交负价单（TRADE-005a）、`quantity:-5` 成交负数量单（TRADE-006b），与 spec TRADE-005/006「400 明确拒绝」不符（实现口径备注第 5 条确认）。
5. **下单路径无余额校验、无 20% 单票上限**：TRADE-011/012。大额单仅由「单笔>50 万」RiskManager 拦截；单票可远超 20% 仍成交（20% 仅存在于模拟决策层）。
6. **SIM 决策恒为 0**：26 条有效预测下触发/启动均「生成 0 条交易决策」，导致 SIM-017/018/039 的仓位/资金勾稽无法通过真实成交覆盖（数据/选择逻辑待核）。

**环境/配置说明**
- REAL_TRADING_ENABLED=false（默认）→ TRADE-010 因无法产出真实单而标记阻塞（非缺陷，配置所致）。
- SIM-034 盘后结算需 15:00 后运行，测试时刻未到，标记阻塞。
- TRADE-018~020/036~039、SIM-019/020/035~038 为前端交互用例，本任务为 API 执行，标记「前端交互不可覆盖（NULL）」，需浏览器回归。
