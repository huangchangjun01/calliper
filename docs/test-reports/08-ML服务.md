## 全局性环境事实（影响多条用例）

1. **鉴权未启用**：`.env`（`ml-service/.env`）仅含 `DATABASE_URL`/`TSDB_URL`，无 `ML_API_KEY`。`POST /api/v1/predictions/batch`（无 key → 200、错 key → 200）、`POST /api/v1/predictions/run`（无 key → 200）均证明写端点也不鉴权。一切 `{"detail":"Invalid or missing API key"}`（401）类断言均无法成立。
2. **symbol 解析差异（关键）**：运行中的 ML 服务仅能解析**裸数字代码**（`600519`、`000001` → 特征 39 项、预测正常 200），**不解析**交易所后缀（`600519.SH`/`000001.SZ`）与字母代码（`AAPL`）。用例按 spec/README 使用 `600519.SH`/`AAPL`，导致单只预测 404、特征空数组、批量预测空数组。属 symbol→数据映射不一致（数据由主库 stocks/TSDB 以数字代码存储）。
3. **模型/cnverse**：三模型均已训练 healthy 且与 versions.json 一致（short v2.0.7-real/0.5、medium v2.0.4-real/0.4083、long v2.0.4-real/0.786）；`is_healthy`=true；`model_type`/`framework` 与备注 17 一致。
4. **服务稳定性风险（严重）**：执行 `POST /predictions/run?period=all`（100 只全量后台预测）与 `POST /models/short_term/evaluate`（评估需 `load_real_frames` 全量加载+推理）时，服务进程**先后两次整体退出**（端口 8000 失联，无 python 进程，需人工重启 uvicorn）。评估接口 400s 内未返回、最终压垮进程。评估/全量预测在当前数据量下对服务负载过高。
5. 中文 `direction`/刀片名在 PowerShell `-UseBasicParsing` 下以 GBK 控制台显示乱码（如 `"åä¸è·"`）；已用 `WebClient.DownloadFile`+UTF-8 读取验证服务端字节正确（`"direction":"下跌"`），**非服务缺陷**，属控制台显示伪影。

## 问题清单

1. **鉴权未启用**（P1）：`ml-service/.env` 未配置 `ML_API_KEY`，导致 `require_api_key` 全链路未生效，写端点（batch/run/train/evaluate/rollback/params-PUT）无 key 也 200。ML-001/002 鉴权 401 用例无法通过。需按部署规范注入 `ML_API_KEY` 后重测鉴权；同时隐忧：若上线忘配置则写端点裸奔。
2. **symbol 解析不一致**（P1，集成）：ML 服务仅解析裸数字代码（`600519`），无法解析 `600519.SH`/`000001.SZ`/`AAPL`。get 单只预测/特征对带后缀 symbol 返回 404/空，批量空数组。功能本身正常（裸代码全部通过），但对外暴露的 symbol 格式（spec 用例用 `600519.SH`）与服务内部解析不一致，需网关/服务层统一 symbol 规范化。
3. **features/compute computed 计数口径偏差**（P2）：`computed` 直接等于输入 symbols 数量（含无数据符号也在 results 中以空 features 出现，如 NONEXIST123），与 spec「跳过无数据符号、computed=成功计算数」不符。ML-038 复现（`["600519","NONEXIST123"]` → computed=2）。建议在 `features.py` compute 端对空 features 的符号不计入 computed 并过滤。
4. **评估/全量预测压垮服务**（P1，严重）：`POST /models/{period}/evaluate`（及 `run?period=all`）在真实数据全量加载+推理下，请求长达 400s 未返回并导致服务进程整体退出（测试期间服务两次崩溃、端口 8000 失联，均需人工重启 uvicorn）。评估类、全量 run 用例被阻塞。需评估该重操作是否应改异步/限流/分页，或确认是否数据量或硬件导致 OOM/超时。
5. **控制台中文乱码为显示伪影**（提示，非缺陷）：PowerShell `-UseBasicParsing` 下 `direction`/刀片名以 GBK 显示乱码；用原生 UTF-8 读取确认服务端字节正确（`"direction":"下跌"`）。
6. **需注意**：`GET /predictions/accuracy/{symbol}` 的 `total_predictions=100` 为进程内 run 摘要计数（占位口径），与备注 13 一致，重启后归 0。
