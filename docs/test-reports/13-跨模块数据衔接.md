## 一致性比对问题清单（跨模块数据衔接缺陷汇总）

1. **【缺陷·P1 / LINK-005】置信度标尺不匹配（阻断整个模拟交易决策链）**：`predictions.confidence` 落库为 0-1（范围 0.35~0.80），而 `SimTradeService` 决策过滤写死 `confidence >= 55` / 买入门 `>= 60`（0-100 语义），导致**任何本地有效预测都无法进入决策**，`runDecisionCycle` 恒产出 0 决策 → 决策→成交→持仓/资金全链路（LINK-005/018）常态不可达。需统一置信度口径（DB 归一为 0-1 后按 0.55/0.60 比较，或比较前 ×100）。
2. **【已知缺陷·P1 / LINK-005】手动下单不改 sim_accounts 余额**：手动限价买 100@9.30（filled）仅更新 `orders`/`positions`，`sim_accounts.available_cash` 不扣减（资金不勾稽）；`TradeService.PlaceOrder` 不维护 sim_accounts，与 `SimTradeService`（ExecuteTrades→recalculateAccount）为两套资金口径。
3. **【缺陷·P1 / LINK-004】股票检索 market 过滤 SQL 歧义列**：`GET /stocks/search?q=...&market=...` 在 `JOIN markets` 后未限定 `name`/`name_cn`，报 500 `SQLSTATE 42702`。不带 market 正常。
4. **【口径偏差·P1 / LINK-012】行情采集有效间隔 ≈40-50s 而非 5s**：`MARKET_COLLECT_INTERVAL_SEC` 默认 5s 未生效于有效节奏——每轮采集 ~202 只（主源+回源）耗时 ~40s，TSDB tick / WS 推送均按 ~45s 推进。若需 5s 级 tick 需收敛采集标的或加速回源。
5. **【口径偏差·P2 / LINK-010】legacy 预测 valid_until 异常**：早于 09:30 生成的 short 预测 `valid_until` 为固定值 `2026-09-03 09:28:31`（非 +3 天），疑旧版本 GenerateAndPersist 产物，建议核对历史数据迁移。
6. **【环境口径·P2 / LINK-001,004】symbol 表示不一致**：用例/文档使用 `600519.SH`，环境 stocks/TSDB/Redis 只有裸数字代码 `600000` 等，`600519.SH` 不在 stocks 表（行情/落库均以裸码为键）；对外 API 需统一 symbol 规范化后方可对上用例标的。
7. **【数据异常·P2】生成预测 target_price 为负值**（如 -0.15/-0.16），使 `MakeDecision` 无法计算预期收益率（`ExpectedRet` 仅在 target>0 时计算），进一步削弱决策可运行性。
8. **【说明】评估/训练类重活**：ML 侧 `GET/POST /models/*/evaluate` 与全量预测在真实数据下负载极高（此前曾压垮服务），LINK-002 的 ML `versions.json` 回写、LINK-011 的 train-apply 均未实跑，以代码/DB 侧核验替代，避免破坏共享服务。
