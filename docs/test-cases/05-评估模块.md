# 05 — 评估模块 测试用例

本文件覆盖**评估模块**（evaluation）的全部测试用例，编号 `EVAL-001` 起。EVAL-001 ~ EVAL-010 为 spec 基准用例（编号、维度、优先级、标题、预期结果与 spec 保持一致），EVAL-011 起为补充用例（排行 limit 参数、metrics 字段完整性、评估并发触发、无数据空态、401/403 门禁、每日调度自动触发、阈值口径、前端交互等，基于后端源码与前端实现核验后补充）。

## 覆盖端点

| 端点 | 鉴权 | 说明 |
|---|---|---|
| `GET /api/v1/evaluation/accuracy/:symbol/stats` | 需 JWT | 个股准确率统计（近7/近30/累计 + by_period） |
| `GET /api/v1/evaluation/accuracy/:symbol` | 需 JWT | 个股准确率（与 /stats 同实现，返回完整 AccuracyStats） |
| `GET /api/v1/evaluation/ranking` | 需 JWT | 个股准确率排行（period/limit 参数，30 日窗口） |
| `GET /api/v1/evaluation/metrics/:symbol` | 需 JWT | 评估指标（超额收益/夏普/最大回撤） |
| `GET /api/v1/evaluation/failure/:symbol` | 需 JWT | 失败归因分析（需 `prediction_id` 查询参数） |
| `POST /api/v1/admin/evaluation/run` | 需 JWT + admin 角色 | 手动触发每日评估（spec 简写为 `POST /evaluation/run`） |

> 说明：spec 中 `POST /evaluation/run`（admin）在路由注册中的完整路径为 `POST /api/v1/admin/evaluation/run`（`main.go` admin 分组，先 `AuthMiddleware` 再 `AdminMiddleware`，见 `main.go:343`）。本文件统一使用该完整路径。

## 响应约定说明

- 评估模块全部接口使用统一信封：成功 `{"code":0,"message":"success","data":<业务数据>}`；失败 `{"code":<业务码>,"message":"<错误信息>","data":null}`。
- 业务码：`40001` 参数错误（symbol is required / valid prediction_id is required）、`50001` 服务端错误（含 stock/prediction 未找到）、`50301` 评估调度器不可用。
- 鉴权失败：无 token → `401 {"error":"missing authorization token"}`；token 无效/过期 → `401 {"error":"invalid or expired token"}`；非 admin 访问管理端点 → `403 {"error":"admin access required"}`（见 `middleware/auth.go`）。
- 分页统一约定（`parsePageLimit`，见 `handlers/helpers.go`）：`limit` 钳制范围 `[1,100]`，非法/越界值回退默认值（ranking 默认 20）；`offset` 非法或负数回退 `0`。注意 ranking 处理器读取 offset 后丢弃（仅用 limit）。
- 准确率比例口径（重要，两套并存）：
  - 百分制（0~100）：`accuracy/:symbol/stats` 的 `accuracy_7d/accuracy_30d/accuracy_total`、dashboard `accuracy_summary`、`model_health` 判断阈值（45/60）均按 0~100；
  - 小数制（0~1）：`ranking` 的 `accuracy`、预测模块准确率趋势（`/predictions/accuracy`）按 0~1，前端排行图按 0~1 展示并乘 100 转百分比。
- 周期 DB 约定：`short` / `medium` / `long`（`prediction_accuracies.period`、`by_period` 键）。方向 DB 约定：`up` / `down` / `flat` / `bullish` / `bearish` / `neutral`（评估判定写入时由 `directionFromChange` 归一化为 bullish/bearish/neutral）。
- 相关数据表：`stocks`（主库）、`predictions`（主库）、`prediction_accuracies`（主库）、`stock_prices_daily`（TimescaleDB，评估回算行情）。

## 实现口径核验备注（补充用例依据）

1. **run 路由位置**：`POST /api/v1/evaluation/run`（spec 简写）实际注册于 admin 分组 → `POST /api/v1/admin/evaluation/run`，无 token 401、非 admin 403。
2. **`/accuracy/:symbol` 与 `/accuracy/:symbol/stats` 同实现**：`GetAccuracy` 与 `GetAccuracyStats` 均调用 `evalService.GetAccuracyStats(symbol)`，两者返回相同的完整 `AccuracyStats` 结构（含 `by_period`），并非"基础准确率"与"详细统计"之分（见 `evaluation_handler.go:36-68`）。
3. **symbol 未找到返回 500 而非 404**：`GetAccuracyStats` 查 `stocks` 表，未命中返回 error，处理器转为 `500 {"code":50001,"message":"stock not found: <symbol>"}`；`AnalyzeFailure` 同理（stock/prediction 未找到均 500）。metrics 例外——`GetMetrics` 内部吞掉各子指标错误并降级返回全 0（不 500）。
4. **metrics 字段与 spec 不符**：spec EVAL-004 预期"方向准确率/夏普/回撤"，实际返回 `excess_return`（超额收益，基于 simulated_trades 与基准 000001 指数）、`sharpe_ratio`、`max_drawdown`，**不包含方向准确率**。
5. **failure 需 `prediction_id` 参数**：spec EVAL-005 未体现该参数；实现中 `prediction_id` 为必填（默认 "0"，缺省/非法 → `400 {"code":40001,"message":"valid prediction_id is required"}`）。
6. **failure `actual_direction` 硬编码**：`AnalyzeFailure` 中 `ActualDirection` 恒为 `"bearish"`（`evaluation_service.go:646`），未按真实行情回填；`is_earnings_season` 按当前月份判断（1-4/7-8/10 月为财报季）。
7. **低准确率挂起口径（EVAL-008）**：`GetModelHealth` 的 `suspend` 依据**全局** 30 日准确率（`GetAccuracySummary` 全市场统计）< 45，并非单只股票；"该股不再出现在高置信度推荐"在实现中不成立——dashboard `high_confidence` 仅按 `confidence ≥ 60/100`（阈值换算为 0.6）过滤 pending 预测，**未按个股 30 日准确率剔除**（关联 DASH-003 差异，记录在案）。
8. **连续低准确率重训口径（EVAL-009）**：`GetModelHealth` 的 `consecutive_below_threshold` 通过 `GetAccuracyTrendData("all",30)` 从最近一天向前统计连续 `accuracy < 60` 的天数（断点日跳过）。**存在比例单位不匹配**：趋势 accuracy 为 0~1 小数，却与 60（0~100 百分制）直接比较，导致任意有评估数据的日（accuracy 恒 <60）都会累计——当前实现下只要最近有 ≥5 个有评估数据的连续日即判定需重训。重训标记通过 `GET /api/v1/dashboard` 的 `system_status.model_health` 体现，评估模块不直接回写 ML 侧 `versions.json`。
9. **无行情顺延**：`EvaluateDaily` 对无 TSDB 行情的过期预测跳过（`getActualChange` 返回 ok=false），`predictions.success` 保持 NULL（待验证），不写 `prediction_accuracies` 记录。
10. **EvaluateDaily 幂等**：仅处理 `success IS NULL AND valid_until <= now` 的预测，重复触发不重复评估已判定记录；`RunEvaluation` 为**同步**执行（`EvaluateDaily`，context 超时 5 分钟），手动触发期间请求阻塞直至完成。
11. **调度口径**：`EvaluationScheduler` 每日 15:30 CST（A股）自动执行，`nextEvaluationTime` 为"今日 15:30 前 → 今日 15:30，否则次日 15:30"；`Start` 有 `isRunning` 互斥保护，重复 Start 被忽略；评估超时 5 分钟。
12. **前端数据来源**：前端"预测"页"预测成功率统计"（AccuracyChart + StockAccuracyChart）与"预测失败归因分析"（FailureAnalysis）分别调用 **PRED 模块** 端点 `GET /predictions/accuracy`、`GET /predictions/stock-accuracy`、`GET /predictions/failures`；前端无任何 `/evaluation/*` 引用，EVAL 模块端点为后端专用，无独立前端页面消费（交互用例据此描述）。
