# 07 — 管理后台与模型管理 测试用例

本文件覆盖**管理后台**（admin）模块的全部测试用例，编号 `ADM-001` 起。ADM-001 \~ ADM-025 为 spec 基准用例（编号、维度、优先级、标题、预期结果与 spec 保持一致），ADM-026 起为补充用例（缺字段、权限即时生效、训练并发、审计日志内容完整性、401/403 门禁细化、前端独立 loading 态、表格对齐等，基于后端源码与前端实现核验后补充）。

## 响应约定说明

- 统一信封（`handlers/stock_handler.go`）：成功 `{"code":0,"message":"success","data":<业务数据>}`；失败 `{"code":<业务码>,"message":"<错误信息>","data":null}`。业务码：`40001` 参数错误、`40401` 资源不存在、`40901` 冲突、`50001` 服务端错误、`50301` 数据库不可用、`50302` ML 服务不可达。

- 中间件错误**不走信封**：无 token → `401 {"error":"missing authorization token"}`；token 无效/过期 → `401 {"error":"invalid or expired token"}`；非 admin 角色 → `403 {"error":"admin access required"}`（见 `middleware/auth.go`）。

- **透传端点不套信封**：`GET/PUT /admin/models/:id/params`、`POST /admin/models/:id/evaluate`、`POST /admin/models/:id/predict`、`POST /admin/training/rollback` 直接 `c.JSON(statusCode, <ML 原样响应>)`；非法模型 id 返回 `400 {"error":"invalid model id"}`；ML 不可达返回 `503 {"error":"ML服务不可达"}`。

- 分页统一约定（`parsePageLimit`，`handlers/helpers.go`）：`limit` 钳制范围 `[1,100]`，非法/越界回退默认值（users=50、audit-log=100、training/history=20）；`offset` 非法或负数回退 `0`。

- 训练/评估为**异步执行**：`POST /admin/training/run`、`POST /admin/models/:id/evaluate` 立即返回，后台 goroutine（`util.SafeGo`）以 `trainClient`（HTTP 超时 **7200s**，见 `admin_handler.go` L74）同步调用 ML，完成后回写 `model_training_logs` / 由 ML 回写 `versions.json`。

- 鉴权模型：JWT 内嵌 `role` claim（登录时签发），`AdminMiddleware` 只校验 JWT 中的 role，**不查 DB**。因此角色变更对**已发放 token 不即时生效**，需重新登录获取新 token；用户停用仅拦截**下次登录**（登录 SQL 带 `is_active = true`），存量有效 token 到期前仍可访问（见 `handlers/auth.go` L56、`middleware/auth.go` L75）。

## 实现口径核验备注（补充用例依据）

1. **创建/更新/删除用户的响应体**：`POST /admin/users` 成功返回 `data` 为 `AdminUserDTO`（id/username/email/role/status/createdAt）；`GET /admin/users/:id` 返回**原始 User 模型**（字段为 `is_active/created_at` 等 snake\_case，非 DTO 的 `status/createdAt`）；`PUT/DELETE` 返回 `data` 为 `{"message":"..."}`。
2. **前端 api 客户端解包** **`data`**（`services/api.ts` L103-104 `return json.data`）：透传端点返回的原始 JSON（无 `data` 字段）在前端解析为 `undefined` 业务载荷，仅以 HTTP 状态判定成败；`useEvaluateModel/useTriggerPrediction/useUpdateModelParams/useRollbackModel` 均不消费响应体，故功能正常。
3. **审计日志来源**：`audit_logs` 表仅由 `services/trade_service.go` 写入（place\_order / cancel\_order / account query 三条，见 L100-101、L137-142、L273-274）；**admin 用户 CRUD、训练、评估等管理操作当前不写审计日志**。ADM-044 以"先下单再查审计"验证内容完整性。
4. **模型按钮独立 loading 口径**（`components/ModelManagement/index.tsx`）：训练按钮按行（`runningPeriods` 集合驱动）、评估按钮按行（`evaluatingIds` 记录触发前准确率，准确率变化后自动复位）各自独立；**预测按钮使用共享** **`predictMutation.isPending`（全局），点击某行预测会使所有行预测按钮同时 loading**——训练/评估满足"每行独立"，预测为全局 loading（ADM-024 按 spec 验证训练按钮，预测全局 loading 记录在 ADM-075 备注）。
5. **全量训练按钮**：`loading={runTrainingAll.isPending || runningPeriods.size>0}`、`disabled={runningPeriods.size>0}`；`useRunTraining` 实例化为 `runTrainingAll` 与 `runTrainingOne` 两个独立实例，避免全量/行内训练 loading 互相阻塞。
6. **训练历史轮询**：`useTrainingHistory` 在存在 running 记录时每 5s 自动轮询刷新，全部结束后停止轮询。
7. **占位接口**：`/admin/datasources`、`/admin/health`、`/admin/errors`、`/admin/latency` 均返回 `status:"not_implemented"`；`SystemMonitor` 对 `/admin/latency` 的 `redisHitRate` 直接取值渲染 `Progress`（占位响应无该字段 → percent 为 NaN，存在潜在展示问题，ADM-047 记录）。
8. **训练并发防护**：`RunTraining` 先清理超过 `staleTrainingWindow`（30 分钟）的滞留 running 记录，再拒绝存在 running 记录的同一周期重复训练（`400 code=40001 模型 <period> 正在训练中，请稍后再试`）。
9. **模型列表降级**：`GET /admin/models` 在 ML 不可达/非 200/解析失败时返回 `200 data{status:"degraded", message, models:[]}`（前端据此展示 Alert）；`GET /admin/models/status`（predictionHandler）在 ML 不可达时返回 `500 code=50001`。两端口径不同。
10. **模型 id 合法值**：`short_term` / `medium_term` / `long_term`；`shortPeriod` 去掉 `_term` 后缀映射为前端 `short/medium/long`；`trainingTargetPeriods("all")` 展开为三个周期。
