# 08 — ML 服务 测试用例

本文件覆盖 **ML 服务**（ml-service，FastAPI）模块的全部测试用例，编号 `ML-001` 起。ML-001 \~ ML-027 为 spec 基准用例（编号、维度、优先级、标题、预期结果与 spec 保持一致），ML-028 起为补充用例（GET 预测非法 period、batch 空列表、参数合并不覆盖其它键、回滚后预测一致性、训练并发、无数据时 status/health 行为、读端点鉴权边界、评估/训练回写核验等，基于源码逐文件核验后补充）。

## 响应约定说明

- **错误响应结构**：FastAPI `HTTPException` 统一返回 `{"detail": "<message>"}`（与 Go 网关的 `{"error":...}` 不同）；Query/Pydantic 校验失败返回 **HTTP 422**（如 `limit` 越界 `ge=1, le=100`）。

- **鉴权模型**（`app/security.py`）：仅当环境变量 `ML_API_KEY` 非空时才强制鉴权；`require_api_key` 仅挂载于**写端点**。缺失/错误 key 返回 `401 {"detail":"Invalid or missing API key"}`，响应头带 `WWW-Authenticate: ApiKey realm="ml-service"`。**读端点不校验 key**（见备注 1 与 ML-052）。

- **异步语义**：`POST /predictions/run` 后台线程异步执行，接口立即返回；`POST /models/train/{period}`、`POST /models/{period}/evaluate`、`POST /models/evaluate` 通过 `run_in_threadpool` 在**工作线程**同步执行（HTTP 请求等待其结果，但事件循环不被阻塞）。

- **通用断言**：返回 200 不代表通过，需断言关键响应字段（`period`/`direction`/`confidence`/`accuracy`/`version`/`status` 等）与数值范围；异常输入不得导致 500 或进程崩溃。

## 测试环境准备

- ML 服务（FastAPI）启动于 8000 端口（虚拟环境 `ml-service/.venv`，见 README）。

- 需配置环境变量 `ML_API_KEY`（如 `test-key`）以启用鉴权；需鉴权用例统一携带请求头 `X-ML-API-Key: test-key`。

- 需有真实行情数据（TSDB `calliper_tsdb` 的 `stock_prices_daily`，主库 `stocks` 表存在 symbol 映射；或真实 API 兜底）。测试股票按 README 约定使用 `600519.SH`、`000001.SZ`、`AAPL` 等；模型权重目录 `ml-service/.ml-models/`。

- 无效 symbol：`NONEXIST123`、`""`、超长字符串。

## 实现口径核验备注（补充用例依据）

1. **鉴权覆盖范围**（`security.py`）：`require_api_key` 仅挂在 `POST /predictions/batch`、`POST /predictions/run`、`POST /models/train/{period}`、`POST /models/{period}/rollback`、`POST /models/{period}/evaluate`、`PUT /models/{period}/params`、`POST /models/evaluate` 七个端点；读端点（`GET /predictions/{symbol}`、`GET /predictions/{symbol}/history`、`GET /features/*`、`GET /models/status`、`GET /models/schedule`、`GET /models/{period}/params`、`GET /models/health`）与 `POST /features/compute` **均不校验 key**（`ML_API_KEY` 未配置时全部端点不鉴权，保持向后兼容）。
2. **错误响应为** **`{"detail":...}`**：FastAPI 默认（非 Go 网关信封）；422 用于 Query/body 校验失败。
3. **run 接口参数形式**：`POST /api/v1/predictions/run` 的 `period` 为 **query 参数**（`?period=short_term`），非 body；spec 的 body 写法 `{"period":...}` 实际不生效。返回 HTTP **200**（FastAPI 默认状态码），spec 记为 "202 accepted"——语义一致（后台线程异步执行 `run_daily_prediction(period=...)`）。
4. **训练同步返回**：`POST /models/train/{period}` 通过 `run_in_threadpool` 等待训练完成（HTTP 200 + `TrainingResult{period,status:"success",new_version,accuracy}`）；训练期间 `GET /models/status`、`GET /models/health` 即时响应（ML-025）。
5. **拒训口径**：`load_real_frames` 无任何 ≥120 根真实日线股票时 → 404 `No real training data available; refusing to train on synthetic data`（ML-013）；`prepare_period_data` 返回 None → 404 `No enough real data to train {period}`（ML-014，正常数据条件下因 MIN\_ROWS=120 ≥ 各周期窗口需求而难黑盒触发，见 ML-014）。
6. **训练数据窗口**（`train_models.py prepare_period_data`）：short 滑窗 `seq=30`、`horizon=3` 日、阈值 ±0.5%；medium `horizon=10` 日、阈值 ±2%（逐日单样本、无滑窗）；long 滑窗 `seq=52`、`horizon=30` 日、阈值 ±5%；`MIN_ROWS=120`、`HISTORY_DAYS=1825`；三分类标签（`label_fwd`：>up→2 上涨、<-down→0 下跌、其余→1 震荡）。预测侧滑窗 `_INFERENCE_WINDOW`：short=30、long=52（`prediction_task.py`）。
7. **评估口径**（`prediction_task.py run_model_evaluation` L316-325）：`split = max(len(y)//5, 1)`，验证集取 `X[-split:]/y[-split:]`（时序**最后 ≈20% 样本**，无前视偏差）；`ModelManager.evaluate` 按 `model.LABELS`（三分类）计算 `correct/total` 命中率，随机基线 **33%**；无真实数据返回空 dict → 评估接口返回 `[]`（ML-026/027/051）。
8. **评估回写**：`POST /models/{period}/evaluate`、`POST /models/evaluate` 将 accuracy 回写 `model_manager.versions[period]["accuracy"]` 并 `_save_versions()` 持久化到 `.ml-models/versions.json`；响应中 `precision/recall/f1_score` 字段当前均等值于 `accuracy`（简化实现）。
9. **回滚**（`model_manager.rollback`）：快照文件命名 `{period}_model_v{ver}.{ext}`（short/long=`.pt`、medium=`.pkl`）；`v` 前缀自动补全；快照不存在 → 404 `Snapshot not found for {period} version {version}: {file}`；成功后将快照复制为当前权重、更新 `versions.json` 并 `models[period].load()` 重载内存，**后续预测使用回滚版本**（ML-046）。
10. **训练并发无锁**：`ModelManager.train_single` 与 `POST /models/train/{period}` **无互斥锁**（`PredictionTask._prediction_lock` 仅保护 `run_daily_prediction` / 训练调度路径），并发同周期训练存在 `versions.json`/权重写竞争——与网关侧 ADM"正在训练中"防重不同，属已知实现口径（ML-049）。
11. **调度任务**（`main.py` 注册 + `scheduler.py`）：共 **5 个 job**——`daily_prediction`(每日 15:30)、`pre_market_prediction`(盘前 08:30)、`weekly_training`(周六 02:00)、`daily_training`(每日 17:00)、`model_evaluation`(每日 16:00)；`GET /models/schedule` 返回 `{"jobs":[...]}`，每条含 `id/name/next_run/trigger`；异常/未启动时 `{"jobs":[]}`。
12. **model\_version 口径**：单只/批量预测响应中 `model_version` 字段**固定取** `model_manager.versions["short_term"].version`（`predict_single_stock` 内写死），与请求/命中周期无关（ML-058）。
13. **accuracy 占位**：`GET /api/v1/predictions/accuracy/{symbol}` 为占位实现，`accuracy_7d/30d/total` 恒 0.0，`total_predictions` 取内存摘要 `total_stocks`（未 run 过为 0）（ML-057）。
14. **预测历史为内存态**：`get_prediction_history` 读 `prediction_task.prediction_history`（进程内 list），重启丢失；未触发 run 时为 `[]`；异常时返回 200 `[]`（ML-033）。
15. **features 无数据行为**：`GET /features/{symbol}` 在无真实数据时 `compute_features` 返回 `{}` → 200 **空 features 数组**（非 404）（ML-036）；`features` 类别映射：technical（默认）、fundamental（`fund_*` 前缀）、sentiment（`volume_ratio/money_flow/vwap`）、price（`returns/volatility`）。
16. **`POST /features/compute`** **未挂鉴权**：该写端点不要求 `X-ML-API-Key`，与 `/predictions/batch` 等鉴权写端点不一致（安全口径记录，ML-059）。
17. **模型类型映射**（`models.py _build_model_status`）：short=`LSTM/PyTorch`、medium=`XGBoost+LightGBM Ensemble/scikit-learn`、long=`Transformer/PyTorch`；`is_healthy = versions.json 中 path 非空 且 权重文件存在`。
18. **方向取值**：short/medium 预测 `direction ∈ {"下跌","震荡","上涨"}`；long ∈ {"下跌趋势","震荡趋势","上涨趋势"}；`confidence ∈ [0,1]`；`target_price` 由当前 close 按方向映射系数计算（`target_price_map`）。
19. **参数约束**（`PARAM_LIMITS`）：short `{hidden_size[32,512], num_layers[1,12], dropout[0,0.8]}`；medium `{xgb_max_depth[2,15], xgb_learning_rate[0.001,1], lgb_num_leaves[7,255]}`；long `{d_model[64,1024], nhead[1,32], num_layers[1,12]}`。`set_params` 校验未知键/非数值（含 bool）/越界，缺省键用默认值补齐并持久化 `params_{period}.json`。
