# 10 — 全流程贯通（E2E）测试用例

> 本文档为智能量化交易系统「全流程贯通（端到端用户旅程）」的完整测试用例，逐条落实 `docs/.trae/specs/complete-test-case-suite/spec.md` 中 E2E-001~005 基准用例（编号、维度、优先级、标题、预期结果与 spec 保持一致），并补充断线重连、异常中断恢复续跑、多角色并行等端到端用例（序号从 E2E-006 继续）。
> 核心目标：验证**跨步骤、跨页面、跨模块**主链路无断点——即第 N 步产生的数据（token、symbol、落库预测、订单、持仓、账户、训练日志、模型版本等）必须被第 N+1 步正确消费，所有状态机在真实用户旅程中自洽。

## 测试数据约定

- 测试账号：`admin/admin123`（admin 角色）、`testuser/pass1234`（user 角色）；E2E-001/006/009 等新用户旅程使用独立注册账号 `e2e_user/e2e_ui` 等，避免污染公共账号。
- 测试股票：A 股 `600519.SH`、`000001.SZ`；港股 `00700.HK`；美股 `AAPL`、`TSLA`（以 `stocks` 表实际存在的代码为准）。
- 环境：后端(8080)、前端(5173)、ML(8000)、PostgreSQL/TimescaleDB/Redis 均启动；行情需可访问外网数据源。
- 关键口径提醒（来自 06/05 文档核验备注）：
  1. 后端启动时 **`/trading/sim` 调度器自动启动**（`main.go` 无条件 `StartScheduler(bgCtx)`），`GET /trading/sim/status` 初始 `running=true`，start/stop 为幂等切换。
  2. `POST /trading/order` 经 MockBroker **即时成交**（`status="filled"`），真实/模拟由 `is_real` 区分且请求体 `is_real` 永不直接采信（`REAL_TRADING_ENABLED` 默认 false）。
  3. `/trading/account` 与 `/trading/sim/account` **数据同源**（均读取 SimAccount id=1），金额勾稽可跨接口校验。
  4. 预测生成落库 `short/medium/long`；评估 `EvaluateDaily` 仅处理 `success IS NULL AND valid_until <= now` 的预测（**幂等**）；短期预测有效期 3 天，过期未判定时评估会按真实行情回算。
  5. 模拟账户/持仓为全局共享（id=1），**非按用户隔离**；而 watchlist、订单按用户隔离。

## 数据衔接通用约定

- 每个用例的"测试步骤"中，**步骤 N 产生的数据**（token、symbol、落库记录 id、订单 id、持仓、账户快照、训练日志、模型版本等）**必须被步骤 N+1 消费**，并显式标注"用步骤 N 返回的 XX"。
- token 一旦由登录获得，本用例后续所有受保护接口统一携带 `Authorization: Bearer <token>`（不再逐条重复说明，仅首次出现处标注）。
- 断言以具体状态码 + 关键响应字段为准，200 不代表通过，需核对 `count/persisted/status/accuracy/version` 等数值。
