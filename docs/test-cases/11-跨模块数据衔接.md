# 智能量化交易系统 — 跨模块数据衔接（LINK）测试用例

## 概述

本文档覆盖「跨模块数据衔接」专项测试，验证后端 Go 网关、ML Python 服务、前端 React 三端之间以及各模块之间的**数据流转、落库与一致性**。

- **编号规则**：`LINK-<3位序号>`，序号在本文档内连续递增、全局唯一（遵循 `docs/test-cases/README.md`）。

- **维度标签**：本文档用例统一使用「衔接」维度，交叉场景按需追加「异常」「交互」等维度。

- **优先级**：遵循 README 定义（P0 阻断上线 / P1 主要边界 / P2 次要）。

- **测试账号**：`admin/admin123`（admin）、`testuser/pass1234`（user）。

- **测试股票**：`600519.SH`、`000001.SZ`、`AAPL`、`TSLA` 等（详见 README）。

- **环境**：PostgreSQL `calliper_trading`:5432、TimescaleDB `calliper_tsdb`:5433、Redis:6379、网关:8080、前端:5173、ML 服务:8000。

> 每条用例均显式标注「**数据源 → 流向 → 落点 → 一致性校验方式**」，作为步骤核心。

| 测试维度 | 衔接                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

| 测试步骤 | **数据流**：行情数据源(腾讯/东财) → `MarketDataService.CollectMarketDataForSymbols` → 清洗 → 三路落点：TSDB `stock_prices_tick`、Redis `quote:{symbol}`（完整 JSON，TTL 60s）、WebSocket `stock:{symbol}`。步骤1: 触发一次行情采集（如调用 `POST /api/v1/market/backfill` 或等待定时采集，`MARKET_COLLECT_INTERVAL_SEC=5s`），记录触发时间。步骤2: 查询 TSDB：`SELECT time, price FROM stock_prices_tick WHERE stock_id=(SELECT id FROM stocks WHERE symbol='600519.SH') ORDER BY time DESC LIMIT 1`，记录 timestamp 与 price。步骤3: 查询 Redis：`GET quote:600519.SH`（完整 JSON）与 `GET market:realtime:600519.SH`（价格字符串），记录 timestamp/price。步骤4: 以 WebSocket 订阅 `stock:600519.SH`，记录收到的最近一条 `quote` 消息的 `data.timestamp`、`data.price` 与到达时刻。步骤5: **一致性校验**：对比 TSDB / Redis(quote) / WebSocket 三处的 timestamp 与 price，确认同一采集批次；WebSocket 到达时刻 − 采集触发时刻 = 推送延迟。 |
| 预期结果 | TSDB、Redis、WebSocket 三处为同一采集批次数据，timestamp 一致、price 一致；WebSocket 推送延迟 <100ms；Redis `market:realtime` 为 2 位小数价格字符串（与 JSON 的 price 数值一致）；TSDB 按 `(time,stock_id)` 幂等 upsert，同一批次不产生重复行                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
