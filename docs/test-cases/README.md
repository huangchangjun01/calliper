### 3. 测试维度标签

每个用例标注一个或多个维度：

| 维度        | 标识 | 说明                         |
| --------- | -- | -------------------------- |
| 功能符合预期    | 功能 | 验证接口/页面按规格输出正确结果           |
| 全流程贯通     | 流程 | 验证跨步骤/跨页面主链路无断点            |
| 跨模块数据衔接   | 衔接 | 验证模块间数据流转、落库、一致性           |
| 异常输入·异常场景 | 异常 | 非法输入、边界值、依赖服务故障、权限越权       |
| 前端友好交互    | 交互 | 加载态/空态/错误态/表单校验/跳转/刷新/可访问性 |

扩展标签（用于更精确地标注子类，均映射回上述主维度）：

- `边界`（参数上下限/截断）→ 主维度「异常」

- `门禁`/`鉴权`（权限控制、真实交易开关）→ 主维度「异常」

- `阈值`/`风险`/`风控`（准确率阈值、仓位/亏损风控）→ 主维度「衔接」

- `性能`（超时/并发不阻塞）→ 主维度「功能」

- `数据`（验证集口径、指标定义）→ 主维度「衔接」

### 4. 通用请求约定

- 认证：受保护接口需在 `Authorization: Bearer <token>` 携带 JWT（登录返回）。

- 错误响应统一结构：`{"error": "<message>"}`；交易类接口返回 `{"code": <int>, "message": "<msg>"}`。

- 管理后台接口需要 admin 角色（`GET /api/v1/admin/*`）。

### 5. 通用断言约定

- 返回 200 不代表通过，需断言关键响应字段与数值（如 `count`、`total`、`accuracy`、`status`）。

- 异常输入不得导致 500 或进程崩溃；依赖不可用时应有明确错误信息或空态降级。

- WebSocket 类用例需校验消息类型、字段、推送时效（<100ms）与重连行为。
