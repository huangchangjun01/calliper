# 06 — 交易与模拟交易 测试用例

本文件覆盖**交易模块（真实/模拟下单）** 与 **模拟交易模块（决策/风控/历史）** 的全部测试用例，编号 `TRADE-001` / `SIM-001` 起。TRADE-001 ~ TRADE-020 与 SIM-001 ~ SIM-020 为 spec 基准用例（编号、维度、优先级、标题、预期结果与 spec 保持一致），TRADE-021 / SIM-021 起为补充用例（市价/限价差异、下单并发、撤单竞态、股票不存在、卖出持仓校验、401 门禁、模拟交易调度时间、历史分页、空态/定时刷新等，基于后端源码与前端实现核验后补充）。

## 响应约定说明

- 全部接口使用统一信封：成功 `{"code":0,"message":"success","data":<业务数据>}`；失败 `{"code":<业务码>,"message":"<错误信息>","data":null}`。
- 交易类业务码：`40001` 参数错误（invalid request / order id is required / date 参数不能为空）、`40002` 交易密码不能为空、`40003` invalid price format、`40101` 未授权、`40103` 交易密码错误、`40401` 订单不存在、`50001` 服务端业务错误（股票不存在/风险拒绝/撤单失败等）、`50301` 交易服务不可用。
- 鉴权失败（AuthMiddleware 先于业务处理）：无 token → `401 {"error":"missing authorization token"}`；token 无效/过期 → `401 {"error":"invalid or expired token"}`。
- 分页统一约定（`parsePageLimit`）：`limit` 钳制范围 `[1,100]`，非法/越界/为空回退默认值（orders/trades 默认 20，decisions 默认 50）；`offset` 非法或负数回退 `0`。
- 订单对象字段（`models.Order`）：`id / user_id / stock_id / order_type / order_kind / price / quantity / filled_quantity / status / is_real / created_at / updated_at / stock(omitempty)`。`status` 取值：`pending/partial/filled/cancelled/rejected`；**无 `trade_type` 字段**，真实/模拟用 `is_real`（true=真实，false=模拟）区分。
- 账户对象字段（`AccountInfo`）：`total_assets / available_cash / frozen_cash / market_value / total_pnl / today_pnl`。
- 模拟账户字段（`models.SimAccount`）：`id / total_assets / initial_capital / available_cash / frozen_cash / market_value / total_pnl / today_pnl / today_return / start_date / is_running`。
- 模拟决策视图字段（`SimDecisionView`）：`id / symbol / name / side / price / quantity / confidence / reason / created_at`；成交记录视图字段（`SimRecordView`）：`id / symbol / name / side / price / quantity / profit / profit_percent / created_at`。
- 模拟状态视图（`GET /trading/sim/status`）：`{running, account:{total_asset,available_cash,market_value,today_profit,today_profit_percent,total_profit,total_profit_percent,initial_capital,start_date,is_running}, decisions:[], records:[], risk_control:{max_daily_loss,current_daily_loss,max_position_ratio,current_position_ratio,max_single_stock_ratio,status(normal/warning/danger)}}`。

## 实现口径核验备注（补充用例依据）

以下为基于 `backend/internal/handlers/trade_handler.go`、`services/trade_service.go`、`services/mock_broker.go`、`services/sim_trade_service.go`、`services/risk_manager.go`、`services/position_manager.go`、`services/account_service.go`、`cmd/gateway/main.go` 及前端 `TradingPanel.tsx` / `OrderForm` / `SimTradePanel` / `OrderList` 的核验结论，是补充用例与差异标注的依据：

1. **MockBroker 即时成交**：`MockBroker.PlaceOrder` 恒返回 `status="filled"`、`filled_quantity=quantity`（限价单按给定价格±0.1% 滑点，市价单取 `stock_price_dailies` 最新收盘价）。因此经公开 API 无法直接产生 `pending` 挂单；**撤单成功路径（TRADE-013）需通过 DB 直接插入 `status='pending'` 的订单**作为前置，否则所有订单均为 filled 不可撤。
2. **校验顺序（PlaceOrder）**：① tradeService 空 → 503/50301；② JSON 绑定失败（缺必填 symbol/action/order_type/price/quantity 或 quantity=0）→ 400/40001；③ `trade_password==""` → 400/40002；④ 解析 userID 失败 → 401/40101；⑤ 用户不存在或 bcrypt 校验失败 → 401/40103；⑥ `price` 非数字 → 400/40003。
3. **真实交易门禁**：`isReal = req.IsReal && REAL_TRADING_ENABLED && role=="admin"`，**请求体中的 `is_real` 永不直接采信**；`REAL_TRADING_ENABLED` 默认 `false`。真实成交仍走 MockBroker（无真实券商）。
4. **无余额/单票比例校验（缺口）**：下单服务**不做可用资金校验，也不做 20% 单票仓位上限校验**（20% 仅存在于模拟交易决策与 `PositionManager.CheckPositionLimit`）。与 spec TRADE-011/012 存在差异：最接近的拒绝路径为风险校验 `单笔交易金额 > 500000` → 500/50001"单笔交易金额超过限额"。测试时按缺陷记录。
5. **价格/数量负数未拦截（缺口）**：`price:"-1"`、`quantity:-5` 可通过 decimal/绑定校验并被 MockBroker 成交（产生负价/负数量订单），与 spec TRADE-005/006 的"400/明确拒绝"存在差异，按缺陷记录。
6. **股票不存在口径**：下单时 `stocks` 表查不到 symbol → 500/50001"股票不存在: <symbol>"（业务错误，非 404）。
7. **卖出无持仓/数量不足**：`updatePosition` 校验不足 → 500/50001"无持仓或数量不足"（同一条错误信息）。
8. **撤单**：仅 `pending/submitted` 可撤；filled/cancelled 撤单 → 500/50001"订单状态为 %s，无法撤单"；撤他人/不存在订单 → 500/50001"订单不存在或无权操作"；撤单成功 → 200 `{message:"订单已撤单"}`。
9. **订单详情越权**：`GetOrderByID` 按 `id + user_id` 查询，他人订单 → 404/40401"订单不存在"。
10. **模拟调度器启动即运行**：`main.go` 在 db 可用时**无条件自动启动**模拟交易调度器（`simTradeService.StartScheduler(bgCtx)`），且启动即自动执行首轮决策。因此服务启动后 `GET /trading/sim/status` 初始即 `running=true`，start/stop 语义为幂等切换（详见 SIM-001/002/003/005）。
11. **调度周期与时段**：决策 ticker 15 分钟、结算 ticker 15 分钟；仅在 A 股交易时段（周一~周五 09:30–11:30 / 13:00–15:00，Asia/Shanghai）执行决策；15:00 后执行盘后结算（SettleDaily，更新总资产/市值/今日盈亏/今日收益率并写 Redis `sim:daily_pnl:<date>`）。
12. **决策置信度口径**：`MakeDecision` 先用 `confidence>=55` 过滤并取预期收益 Top20；`buildDecision` 中**买入/卖出还需 `confidence>=60`**（55≤conf<60 记为 hold）。单票上限 20%、行业上限 40% 在 `buildDecision` 内自动压缩数量；已达上限 → hold"已达单票仓位上限"。
13. **风控检查**：每轮 `runDecisionCycle` 先 `CheckRiskLimits`——当日亏损 >5% 时记录 `daily_loss_limit` + `trading_halted` 风险事件并**跳过本轮**；单票 >20%、行业 >40% 仅记录 `single_position_limit` / `industry_exposure_limit` 风险事件（`risk_events` 表），不暂停交易。
14. **模拟成交资金流转**：买入在单事务内完成（锁账户→校验资金→扣可用→持仓 upsert→写 `simulated_trades`）；卖出走 `UpdatePosition` + `UpdateBalance`（金额为正即加回）。模拟账户仅一个（id=1），**模拟持仓/账户为全局共享**（user_id=1），非按用户隔离。
15. **`/trading/account` 与 `/trading/sim/account` 数据同源**：`/trading/account` 由 MockBroker 读取同一 `SimAccount`(id=1) + `is_real=false` 持仓计算市值，故真实 Tab 与模拟 Tab 展示的"账户资产"实为同一模拟资金池（前端真实 Tab 的账户卡片数据源即此）。
16. **前端真实/模拟标识**：`TradingPanel` 用 **Tab（"真实交易"/"模拟交易"）** 区分，而非同一面板的开关；真实 Tab 下 `OrderForm` 固定 `isReal=true`（要求交易密码）、模拟 Tab 渲染 `SimTradePanel`（含启停 Switch、风险条、决策/记录表、历史决策弹框）。模拟 Tab 的 `simStatus` 15s 定时刷新；真实 Tab 的订单/持仓/账户 30s 定时刷新。
17. **前端下单表单**：选股后自动按 symbol 调 `/market/realtime/batch` 回填实时价；`validate()` 前置校验（股票代码/数量>0/限价必填价格/真实交易必填密码）；`submitting` 期间禁用按钮防重复提交；提交前弹 `Modal.confirm` 二次确认；市价单不展示价格输入。
18. **历史日期参数**：`GET /trading/sim/history` 缺 `date` → 400/40001"date 参数不能为空（格式 YYYY-MM-DD）"；`date` 格式非法（如 `abc`）→ **500/50001"日期格式无效: <date>"**（与 spec SIM-012 的 400 表述存在差异，按实际断言，见 SIM-028）。
